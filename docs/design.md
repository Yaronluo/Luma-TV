# 设计与架构 · 0.2

Luma TV 以 tvOS 的空间比例、简洁布局及焦点反馈为参考，使用自有背景和本机真实应用资源。首页不显示大标题、虚构推荐、观看进度或不可用按钮。

## 首页

首页只有两件东西：占满画面的当前应用剧照（stage），以及悬浮在画面下方的磨砂 dock。向下浏览时剧照完全退场，dock 收进网格顶端、与六列应用网格同一节奏展开。dock 直接启动应用；画面本身是焦点区域——左右换台、确认键启动当前应用，与 tvOS Top Shelf 的交互一致。没有可见的横卡、标题、时钟或托盘底板。

托盘显示前五个收藏与“全部应用”。没有收藏时使用前五个电视应用，正式入口先于开发变体。更多收藏和其余电视应用去重后出现在网格中，再提供设置与管理入口。应用数量取决于真实安装情况。

以 960×540dp 逻辑窗口为基准：

| 元素 | 规格 |
|---|---|
| 横向安全区 | 默认48dp，可选56/64dp |
| 剧照 | 当前应用横幅满屏Crop；按画面平均亮度补一层深色（0.22–0.66，白底横幅不会变成灯箱）；换台460ms交叉淡入；焦点在画面上时整体放大1.012；顶部与底部压暗之外再叠一层中低强度暗角；展开网格时完全淡出，屏幕交给壁纸 |
| 悬浮dock | 六格五比三图块110×66dp、间距9dp、内边距13dp，整板731×92dp、圆角26dp，首屏y360dp |
| dock整板 | 只有首屏有板：画面缩略图的模糊切片（160×90取样后拉伸），按画面亮度补深（30%–60%），叠白色10%→2%渐变与26dp阴影，不使用实时backdrop blur；展开后不再画板，同一排图块直接成为网格首行 |
| 图块内容 | 应用自己的宽幅横幅满铺（Crop）——这是 tvOS 图块的本体；没有横幅的电视应用才退回图标：不透明图标满铺，透明标记占高度62%（方形）/56%（宽幅）居中，底色取图标饱和度加权主色并限亮（覆盖率高时上限0.24，否则0.19），无色或过亮时退回深色 `#171C24`；只有图标在绘制后裁掉透明边，横幅保留自己的留白 |
| 应用网格 | 六列五比三图块121.5×73dp、圆角22dp，列距27dp、行距22dp；展开后网格首行y147dp，与首屏dock行（y52dp、高73dp）共用22dp行距，读作同一张网格 |
| 名称 | 只显示焦点项：13sp、焦点淡入；dock 与剧照不显示名称 |
| 焦点反馈 | 图标放大1.075（减少动态效果时1.012）、上移4dp；20dp阴影只在焦点时出现，静止无阴影 |
| 焦点退让 | 焦点在剧照时停掉图标高亮，dock整板加深24%，图标保持不透明 |
| 布局过渡 | dock/网格弹簧（dampingRatio 1、stiffness 380，减少动态效果时瞬切）、压暗220ms、换台460ms，支持连续输入和中断 |
| 网格内容起点 | 首屏y504dp，底部露出36dp提示还有下一行；展开后网格偏移y131dp（首行147dp），dock移至y52dp成为网格首行 |

主文字 `#F5F7F8`、次文字 `#D1DDE1`、强调色 `#D8E9ED`，面板底色 `#354A58`。设置标题32sp、正文18sp、值16sp。减少动态效果独立控制缩放、抬升和过渡。

网格不使用底板、卡片描边或内嵌标题条：图标直接浮在背景上，靠缩放、阴影和压暗表达层级。唯一的面板是首屏的悬浮dock，展开后连它也不画。tv-material 默认的 focus 光晕与描边由 `quietBorder()`/`quietGlow()` 关闭，避免出现非设计的细亮环。

## 背景与资源

默认背景是一面暗场里的雾面石板：左上一束低角度方向光揭示细微矿物颗粒，中段转灰，下三分接近纯黑，色相与界面冷白同族。展开网格时它作为底场，让应用图块成为画面里唯一的亮物。源稿由生成式图像工具制作，实际1672×941；清晰版与模糊版使用相同裁切。`design/export-background.cjs` 将源图外扩、对模糊版执行sigma76px高斯模糊，再导出1920×1080 JPEG，避免边缘黑边。工具需要Sharp，仅用于设计导出，不是Android运行依赖。

Android在IO线程解码并缓存默认图片，不逐帧执行全屏模糊。其他内置背景和导入图片使用三次滑动盒式滤波近似高斯，宽度上限1280，API26+可用。首页默认背景罩层更浅（其他页面罩层强度的22%），因为首屏剧照会把它盖住、展开时它要透出来当底场。首屏剧照覆盖背景并在其上叠加全屏电影感渐变罩层，顶部与底部更深、中段更淡；展开网格时剧照完全淡出，只留壁纸当底场。不使用Apple私有材质，也没有单独的实时backdrop blur——dock的磨砂是把剧照缩到160×90后按比例切出dock区域再拉伸，属于近似。

`backgroundBlur` 默认true，旧配置缺省也为true，与 `reducedMotion` 独立持久化，不按设备内存自动关闭。用户关闭后使用清晰背景及更浅的渐变罩层。旧 `dusk` 键映射当前默认背景，收藏、排序、隐藏及其他背景选择保留。

应用横幅由PackageManager读取，优先TV banner，后台绘制至最多800×450；缺失时使用真实图标，再退回应用首字。缓存上限12MiB，最多两个并行读取任务。图片低分辨率问题不会由放大解决。应用不内置已安装应用的图标包。

## 遥控器与状态恢复

方向键按卡片行列与实际空间位置移动。焦点缩放只改变绘制，不改变布局尺寸。首次进入默认聚焦托盘第一个应用；恢复时优先使用保存的稳定组件ID，应用卸载后回退到相邻位置。

逻辑目标与实际焦点分开维护，连续输入不必等待动画。`DeferredConfirmation` 在延迟焦点请求期间把完整确认按下/抬起交给最新目标，避免打开旧卡片；离开页面前立即取消旧请求。设置右侧内容尚未挂载时，后续上下/确认事件按顺序交给挂载后的内容，不由旧分类消费。

返回键依次处理排序取消、弹窗关闭、设置内容回分类、返回来源页及网格收起。排序、隐藏与恢复均有方向/确认/返回路径，长按只是快捷方式。页面及外部应用返回时恢复原焦点、展开状态和滚动位置，启动应用前先持久化。

## 职责

| 文件 | 职责 |
|---|---|
| `MainActivity` | 窗口、前台恢复、包变化通知 |
| `LauncherModel` | 异步加载、配置更新、启动前位置保存 |
| `AppRepository` | 发现启动入口、读取资源、显式Intent启动 |
| `ConfigStore` | DataStore本机原子持久化 |
| `LumaApp` | 路由、管理弹窗及排序状态 |
| `HomePage` | 剧照、dock、网格、空间导航与焦点恢复 |
| `Theme` / `BackgroundImages` | 统一卡片、按钮及背景处理 |
| `SettingsPage` | 外观、应用管理、默认桌面与关于 |

优先发现电视入口，再按包去重获取普通启动入口。仅显示当前用户下启用、可导出的应用，排除自身。无启动入口的包不显示，普通应用进入兼容分组。应用回到前台重新查询，安装/更新/卸载通知使资源缓存失效。

收藏排序与全部应用排序独立；隐藏不销毁收藏。卸载后保留稳定组件偏好，同组件重装可恢复。组件名变更暂视为新入口，不自动按包迁移。只读取当前用户，不跨用户或读取其他应用私有数据。

本地图片通过系统文件选择器导入，在后台缩采样并保存至应用私有目录，不申请存储权限。应用不声明网络权限，不添加账号、广告、遥测或常驻服务。

## Launcher

普通入口与默认关闭的HOME alias分离。用户主动设置时启用alias，API29+检查ROLE_HOME，否则尝试HOME_SETTINGS。系统返回后分别检查角色和实际Home解析；OEM可能固定Home，状态提示不能替代按键实测。

原桌面始终保留。测试前记录原组件及恢复方式，不禁用原桌面、不使用无障碍抢Home。已知测试模拟器可授予角色，但优先级更高的原桌面仍处理Home，详见[验证记录](validation.md)。

## 后续边界

不预先加入内容聚合、账号、观看记录、云服务或后台常驻服务。继续观看和内容直达必须依赖公开数据、接入方主动提供的数据或合法深链，不能假定可读取其他应用内部观看记录。
