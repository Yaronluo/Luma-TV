## 首页视觉重构

首页按 tvOS 首页的照片参考重做六轮。第一轮去掉托盘底板与卡片描边、改为方形圆角图标，并用`quietBorder()`/`quietGlow()`关闭tv-material默认的focus光晕与细描边，避免出现非设计的1px亮环。第二轮把布局换成“满屏剧照 + 悬浮磨砂dock”：当前应用横幅满屏铺底、dock浮在画面上，dock底板是剧照缩略图的模糊切片，网格仍为六列方形图标。第三轮按第二张参考照片把展开态改成“浅色玻璃顶栏 + 六列宽幅图块”：dock与网格统一为五比三图块，展开时同一块板从磨砂切片切换成浅色玻璃并留在画面顶部，名称只在焦点项下面淡入。第四轮试过把图块换成“品牌色底 + 应用图标”并给剧照加柔焦，观感偏离参考照片，因此第五轮撤回：图块恢复为应用自己的宽幅横幅满铺（只有没有横幅的电视应用才退回图标配品牌底），剧照恢复清晰画面、仅按平均亮度补深，同时保留第四轮中与排版无关的改进——位移改为阻尼比为1的弹簧（此前欠阻尼弹簧越界触发过“Padding must be non-negative”崩溃，已修）、静止无阴影、启动后预取图块素材避免首帧占位字母。第六轮只修用户指出的“展开后第一行看着怪”：去掉dock行背后的玻璃底板与阴影，展开时剧照完全退场交给壁纸，网格首行从178dp提到147dp、与dock行共用22dp行距——展开态读作一张连续网格，dock行不再像一条浮在画面上的横栏。dock与剧照不显示常驻名称，时钟从首页移除。

- 各轮都通过构建与覆盖安装，并在模拟器上实际截图核对：dock持焦、剧照持焦、换台、展开网格与折叠状态。
- 第四轮改版后的13项遥控器用例一次通过（135.63秒），覆盖剧照焦点区/dock/网格的空间移动、展开收起、返回恢复、收藏排序隐藏与设置分类遍历；第六轮再跑仍为13项一次通过（312.50秒）。
- 重构过程中模拟器进程曾两次退出，均使用同一AVD重新启动（未清空数据、未`-wipe-data`），`adb emu avd name`仍为`BILI_TV_API_34`。
- 剧照来自本机已安装应用的TV banner，不是虚构内容；没有横幅的应用使用图标主色渐变加居中图标。

这不是一次完整的视觉验收：实体电视、4K与长时间运行的画面表现仍未验收。

## 默认背景 v3

- 导出仍走 `design/export-background.cjs`：源图外扩到2200×1238后居中裁1920×1080；模糊版sigma28px（v2 为76px，保留光束形状与细颗粒）。清晰版238KB，模糊版113KB。

- 模拟器（`emulator-5554`，1920×1080）实拍首页、展开网格、设置页：展开时壁纸退为底场，光带落在前两行图块之后，下三分近黑处静帧未观察到色带；设置页罩层为100%，暖光压住标题区但文字对比不变。

## 真实应用返回

从Luma正式BILI卡片按确认，实际打开`com.bili.tv`。BILI会消费首页返回键，本次Back后仍在BILI。普通应用模式下按Home进入原系统桌面，重新打开Luma后恢复正式BILI卡片。

这证明重新进入后的恢复，不代表Luma已接管Home。其他应用是否消费Back由各自实现决定。

## 默认Home：该模拟器未通过

此前实测系统能授予Luma HOME角色，但原桌面HOME候选优先级为2、Luma为0，实际解析与Home键仍进入原桌面。ADB设置默认项也未改变实际行为。应用分别显示角色及实际解析状态，不把角色授予当作成功接管Home。

原桌面从未禁用。0.2.0收尾核对时发现Luma候选入口启用，但缺少该轮前置状态快照，无法确定何时启用；已通过遥控器进入“恢复普通应用模式”关闭。最终角色和实际解析均为原桌面，显示配置恢复为1920×1080 / density320，临时包全部移除。

测试环境原桌面为`com.google.android.tvlauncher/.MainActivity`。以下仅为该模拟器的恢复示例，其他设备必须先查询自己的原桌面：

```bash
adb -s emulator-5554 shell cmd package set-home-activity --user 0 com.google.android.tvlauncher/.MainActivity
adb -s emulator-5554 shell am start -n com.google.android.tvlauncher/.MainActivity
```

框架参考：[AOSP chooseBestActivity](https://android.googlesource.com/platform/frameworks/base/+/92432b503189a0422323b2c7ed09bd489cc6099a/services/core/java/com/android/server/pm/PackageManagerService.java)。结论主要依据此测试环境的查询及按键记录，不能直接推断其他型号。

## 尚未验收或存在限制

- **实体电视**：TCL / Xiaomi尚未安装或测试；默认Home、字体、安全区域及性能需要逐机验证。
- **4K**：曾尝试尺寸覆盖，但AVD实际仍为1080p，因此不记为4K通过。
- **性能**：本轮Debug冷启动显示耗时约1.65–3.25秒，不等于首次可操作时间。没有稳定60fps、低端/高端实体电视或长期运行验收。
- **离线**：运行实现不声明网络权限，核心只访问本机资源；未通过切断整个模拟器网络的方式单独验收。
- **本地图片**：导入、缩采样及错误处理已实现，系统选择器完整遥控器路径尚未验收。
- **应用更新**：组件名称改变时暂视为新入口，不自动迁移旧组件的收藏和排序；同组件覆盖更新已验证。
- **普通应用**：没有电视入口的应用可能需要鼠标，其来源页在进程重建后的恢复尚未验收。
- **图片资源**：默认背景源图1672×941，导出1080p缓存，不是4K原生素材。第三方低分辨率横幅放大后可能偏软。
